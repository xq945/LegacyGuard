# LegacyGuard

**数字遗产与账号托管平台**

人一生中会积累大量数字资料：账号恢复说明、重要文档、密钥提示、订阅与资产处置意愿。当一个人长期失联，这些资料往往无人知晓，或者因为平台自动注销而永久消失。

LegacyGuard 解决的是纯工程问题，不是法律问题：

> 用户把敏感资料**加密**托管在平台，指定若干可信联系人，并设置定期状态确认。当用户长期未确认时，系统通过多轮提醒与人工核验确认失联事实，然后按用户预设的意愿，把**特定资产**的访问权交给**特定联系人**。

**环境**：Docker · Docker Compose

## 核心设计原则

1. **用户未响应不等于用户已授权** —— 超时最多推进到"待人工核验"，不存在任何自动授权路径
2. **审批与生效是两个阶段** —— 审核通过后进入等待期，生效前重新校验全部条件
3. **授权判定永不缓存** —— 每次读取敏感内容都查数据库，撤销后立即失效
4. **MySQL 是唯一事实来源** —— Redis 只承载计数、限流与验证码
5. **关键操作与审计同事务** —— 状态变更与审计记录要么都成功，要么都回滚
6. **消息可靠依赖分层** —— 事务发件箱保证不丢，消费者幂等保证不重
7. **平台不托管可直接使用的凭据** —— 只托管加密的说明性资料，不存密码、银行卡密码等

## 安全说明

- 资产内容采用**信封加密**：每份资产独立数据密钥（DEK），由主密钥（KEK）包裹后入库
- KEK 通过环境变量注入，不硬编码、不进镜像、不入仓库
- 密钥丢失意味着资产永久无法解密，这是刻意设计，不使用后门恢复

## 快速开始

```bash
# 1. 启动中间件（MySQL / Redis / RabbitMQ）
cd docker
cp .env.example .env          # 填写密码；LG_JWT_SECRET 用 openssl rand -base64 32 生成
docker compose up -d
docker compose ps             # 等三个服务 healthy

# 2. 编译并跑测试
cd ../backend
mvn test                      # 期望：9 个测试通过

# 3. 启动后端
mvn spring-boot:run
```

访问 http://localhost:8080/actuator/health 应为 `UP`，Swagger 在
http://localhost:8080/swagger-ui.html 。

> ⚠️ 本机 3306 / 6379 若已被占用，`docker/.env` 中的 `MYSQL_PORT` / `REDIS_PORT`
> 需改成非标准端口，并同步设置后端的 `DB_PORT` / `REDIS_PORT` 环境变量。
> 漏设会连到本机那台数据库，表现为"表不存在"。

完整的运行、环境变量与验证说明见 [09-第二阶段说明](docs/09-第二阶段说明.md)。
