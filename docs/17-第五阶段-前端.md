## 17.3 三个关键实现

### ① 身份范围由服务端决定

```ts
// routes 里的 meta.admin 只决定"要不要显示这个页面"
if (to.meta.admin && !auth.isAdmin) return { name: 'home' }
```

路由守卫是**体验层**的拦截：即使有人手动改 URL 进到管理页，接口也会返回 403。
同理，页面上"按权限显示操作按钮"只是减少困惑，真正的判断在后端。

### ② HTTP 拦截器统一处理 401

```ts
if (status === 401) {
  localStorage.removeItem(TOKEN_KEY)
  // 加一个 redirecting 标记，避免并发请求同时 401 时弹出一堆提示
}
```

后端返回的是 `{code, message, data, requestId}`，HTTP 状态码负责粗粒度分类。
5xx 时把 `requestId` 展示出来 —— 用户报障时能直接定位到日志。

### ③ 状态映射封装成函数

后端的状态在 TypeScript 看来只是 `string`，而 Element Plus 表格插槽里的 `row` 更是 `any`。
直接写 `映射表[row.status]` 会触发索引类型错误：

```ts
// 不行：Element implicitly has an 'any' type
:type="CASE_STATUS_TYPE[row.status]"

// 改成函数，既能兜底未知值，也保住调用处类型安全
:type="caseType(row.status)"
```

## 17.4 构建与联调结果

### 构建

```bash
npm run build     # vue-tsc -b && vite build
✓ built in 832ms
```

类型检查零错误。产物 `dist/` 约 873KB（gzip 278KB），主要是 Element Plus 全量引入。

### 联调验证（真实服务）

| 验证项 | 结果 |
| --- | --- |
| Vite dev server 启动 | ✅ 270ms |
| 首页 HTML 返回 | ✅ |
| `/api` 代理到后端 | ✅ 健康检查经代理返回 200 |
| 经代理调用登录接口 | ✅ 请求确实到达后端（空体返回 400） |

### 诚实的边界

**没有做浏览器交互验证。** 当前环境没有可驱动的浏览器，
所以以下内容尚未被真实验证：

- 页面渲染是否正常
- 表单校验、对话框、表格的实际交互
- 各页面之间的跳转与状态保持
- 不同角色看到的界面差异

已经验证的是：类型检查通过、构建成功、服务能起、代理能通、接口契约与后端 DTO 逐字段核对一致。
真正的 UI 验收要等有浏览器环境时补。

## 17.5 前端暴露的一个后端缺陷

写管理端"失联核验"页时发现：`GET /api/admin/heartbeat/verify-queue`
返回的数据里**没有 userId**，而核验接口是 `POST /admin/heartbeat/{userId}/verify` ——
管理端拿到队列却无法发起核验。

已在 `HeartbeatStatusResponse` 中补上 `userId` 字段并同步前端类型。
这类问题只有真正把界面接到接口上才会暴露。
