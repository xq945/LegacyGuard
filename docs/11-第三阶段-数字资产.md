# 11 第三阶段 · 模块二：数字资产

> 这是整个系统里唯一存放"秘密"的模块。加解密、越权判定、留痕都在这里。

## 11.1 交付接口

| 接口 | 方法 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/api/assets` | POST | 已登录 | 创建，内容加密存储 |
| `/api/assets` | GET | 已登录 | 我的资产列表（只有元数据） |
| `/api/assets/{id}` | GET | 所有者 / 已授权联系人 | 元数据 |

## 11.2 加密方案：信封加密

```
KEK（主密钥，环境变量）──包裹──> DEK（每份资产独立，随机 32 字节）
                                     └── AES-256-GCM ──> 明文
```

| 存入 `digital_asset_secret` 的字段 | 长度 | 含义 |
| --- | --- | --- |
| `wrapped_dek` | 80 字符 | Base64(12 字节 IV ‖ 48 字节密文+tag)，用 KEK 包裹 |
| `kek_version` | — | 包裹用的主密钥版本，支持轮换 |
| `cipher_text` | 不定 | 内容密文 |
| `iv` | 16 字符 | GCM nonce |
| `auth_tag` | 24 字符 | GCM 认证标签 |
| `content_hash` | 64 字符 | 明文 SHA-256 |
| `plain_size` | — | 明文字节数 |

**为什么不是主密钥直接加密内容**：主密钥泄露等于全库泄露；轮换密钥要重加密所有数据。
信封加密让每份资产独立，换密钥只需重新包裹 32 字节的 DEK。

### AAD 把密文钉在具体记录上

加密时把 `"asset:" + assetId` 作为附加认证数据。如果有人把 A 资产的密文行
直接改到 B 资产的记录上，解密时 AAD 不匹配会立刻失败，而不是悄悄解出别人的内容。

这也是为什么必须先插入元数据拿到自增 ID、再加密——两步在同一事务内。

## 11.3 访问守卫只有一处

```java
AssetAccessGuard.evaluate(assetId, userId)
  ① 资产不存在/已删除      → 拒绝 NOT_FOUND  → 404
  ② 是所有者本人            → 放行 OWNER_VIEW
  ③ 存在以自己为联系人的生效案件 → 放行 CASE_VIEW
  ④ 其余                    → 拒绝 NO_ACTIVE_GRANT → 403
```

**这里没有任何缓存。** 每次读明文都查库。缓存"这个人有权限"意味着撤销授权后，
用户在缓存过期前还能继续访问——而需求要求撤销立即生效。一次查询的代价远小于一次越权。

## 11.4 两个端到端测试中发现并修复的缺陷

### ① 拒绝请求返回了 422 而不是 403

**现象**：陌生人读取他人资产内容，期望 403，实际 422「业务规则不满足」。

**根因**：拒绝路径要写访问流水，但 `access_type` 传了 `null`，
而该列是 `NOT NULL` 且无默认值。插入失败抛 `DataIntegrityViolationException`，
被全局异常处理器映射成 422，**覆盖了本该返回的 403**。

**修复**：
- 拒绝时 `access_type` 写占位值 `DENIED`
- 更关键的是把留痕失败与安全结论解耦：

| 路径 | 留痕写入失败时 |
| --- | --- |
| **允许**（成功返回明文） | 让整个请求失败 —— 没有留痕的敏感数据访问不该放行 |
| **拒绝** | 记 ERROR 日志，返回值仍然是 403/404 |

这个不对称是有意的：留痕是"证据"，不该有权力改写安全结论。

### ② 内容过大返回了 400 而不是 422

**根因**：DTO 上 `@Size(max=65536)` 数的是**字符数**，而 Service 按 **UTF-8 字节数**校验。
纯 ASCII 内容会先撞上字符数限制，返回 400；中文内容则是字节超限，返回 422。
同一个"内容太长"有两种错误码。

**修复**：去掉 DTO 的长度校验，统一由 Service 按字节判定，结论稳定为 422。

## 11.6 本模块的已知边界

- **软删除不删密文**：拍下 `deleted_at` 后，`digital_asset_secret` 中的密文仍然保留。
  这是刻意的（审计与案件历史需要），但意味着存储只增不减，后续需要归档策略。
- **配额按条数而非容量**：100 条 × 64KB 上限，没有做总容量控制。
- **联系人访问路径尚未联调**：`CASE_VIEW` 分支的查询已写好并在单元测试覆盖，
  但因为授权案件模块还没做，端到端还测不到——模块五完成后补测。
