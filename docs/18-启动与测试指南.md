# 18 启动与测试指南

## 18.1 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 21 | 后端编译与运行 |
| Maven | 3.9+ | 依赖管理与构建 |
| Node.js | 22+ | 前端构建 |
| Docker | 24+ | 中间件与镜像构建 |

## 18.2 方式一：本地开发（推荐）

### 步骤 1 · 启动中间件

```bash
cd docker
cp .env.example .env
```

编辑 `.env`，至少填写：

```
MYSQL_ROOT_PASSWORD=<随机强密码>
DB_PASSWORD=<随机强密码>
RABBITMQ_PASSWORD=<随机强密码>
LG_JWT_SECRET=<执行 openssl rand -base64 32 生成>
```

> ⚠️ **端口冲突**：如果本机已经装了 MySQL 或 Redis，把 `.env` 里的
> `MYSQL_PORT` 和 `REDIS_PORT` 改成非标准端口（例如 13306 / 16379）。
> 忘记同步后端的 `DB_PORT` / `REDIS_PORT` 会连到本机那台库，表现为"表不存在"。

```bash
docker compose up -d
docker compose ps        # 等三个服务都 healthy
```

首次启动时 MySQL 会自动执行 `sql/schema.sql` 建表。

### 步骤 2 · 导入演示数据（可选）

```bash
docker exec -i lg-mysql mysql -ulegacyguard -p<DB_PASSWORD> legacy_guard < sql/demo-data.sql
```

会创建三个账号与三条加密资产：

| 账号 | 密码 | 角色 |
| --- | --- | --- |
| `admin` | `Admin@12345` | 审核管理员 |
| `owner` | `Owner@12345` | 资产所有者（持有三条资产） |
| `contact` | `Contact@12345` | 可信联系人（与 owner 已生效） |

> 演示资产的密文用**开发环境主密钥**加密。若你改了 `LG_KEK_KEYS`，这些密文将无法解密 ——
> 此时删掉演示资产，在界面上重新创建即可。

### 步骤 3 · 启动后端

```bash
cd backend
export DB_HOST=localhost DB_PORT=13306
export DB_USER=legacyguard DB_PASSWORD=<见 docker/.env>
export REDIS_HOST=localhost REDIS_PORT=16379
export RABBITMQ_HOST=localhost RABBITMQ_PORT=5673
export RABBITMQ_USER=legacyguard RABBITMQ_PASSWORD=<见 docker/.env>
export LG_JWT_SECRET=<见 docker/.env>
mvn spring-boot:run
```

端口以 `docker/.env` 中实际映射为准。

启动成功的标志：

```
Started LegacyGuardApplication in 9.0 seconds
```

访问 http://localhost:8080/actuator/health ，`db` / `redis` / `rabbit` 都应为 `UP`。

### 步骤 4 · 启动前端

```bash
cd frontend
npm install
npm run dev
```

访问 http://localhost:5173 。开发服务器会把 `/api` 代理到 8080，不需要处理跨域。

## 18.3 方式二：全容器

```bash
cd docker
docker compose --profile app up -d --build
```

| 服务 | 地址 |
| --- | --- |
| 前端 | http://localhost:8081 |
| 后端 API | http://localhost:8080 |
| Swagger | http://localhost:8080/swagger-ui.html |
| RabbitMQ 管理台 | http://localhost:15673 |

前端容器的 nginx 会把 `/api` 反代到后端容器，前后端同源。

> `docker compose down -v` 会删除数据卷 —— 包括加密资产的**密文**。
> 密文没了，即便 KEK 还在也解不出任何东西。日常开发不要加 `-v`。

### 后端集成测试（Testcontainers）

```bash
cd backend
mvn verify
```

会先跑完 94 个单元测试，再启动 **真实 MySQL + Redis + RabbitMQ** 三个容器跑 5 个集成测试。首次约 1 分钟。

| 用例 | 验证内容 |
| --- | --- |
| 加密存取 | 明文经接口读写往返，库中密文不可读 |
| 越权拦截 | 陌生人访问返回 403，且访问流水记录 `DENIED` |
| 授权闭环 | 建案 → 审批 → 等待期 → 生效 → 撤销后 403 |
| 异议阻断 | 异议中扫描生效数为 0，状态停在 `DISPUTED` |
| 消息投递 | 事件入发件箱 → 发布 → 消费者落库 |

**前置条件**：本地需已有 `mysql:8.0`、`redis:7`、`rabbitmq:3.12-management` 镜像
（执行过 `docker compose up` 就有）。测试刻意使用 `imageName -> false` 的拉取策略，
避免在无法访问 Docker Hub 的环境里卡住两分钟。

同时关闭了 Testcontainers 的 Ryuk 回收容器（`TESTCONTAINERS_RYUK_DISABLED=true`），
原因相同：Ryuk 镜像需要从 Docker Hub 拉取。容器仍会在 JVM 正常退出时清理。

## 18.5 演示脚本

用演示数据走一遍完整业务闭环：

| 步骤 | 账号 | 操作 |
| --- | --- | --- |
| 1 | — | 数据库执行：`UPDATE heartbeat_confirm_config SET status='REVIEWING' WHERE user_id=2;` |
| 2 | `contact` | 授权案件 → 新建申请 → 勾选资产 → 提交审核 |
| 3 | `admin` | 案件审核 → 受理 → 批准（填审批意见） |
| 4 | `contact` | 刷新案件详情 → 状态变成「等待期」，此时访问资产仍是 403 |
| 5 | `admin` | 案件审核页 → 「触发等待期扫描」 |
| 6 | `contact` | 案件详情 → 查看资产内容（能看到明文） |
| 7 | `owner` | 案件详情 → 撤销授权 |
| 8 | `contact` | 再读资产 → 403（无缓存，立即失效） |

### 演示异议打断生效

在第 4 步之后（等待期内）：

| 步骤 | 账号 | 操作 |
| --- | --- | --- |
| 1 | `owner` | 案件详情 → 提出异议 → 案件转为「异议中」 |
| 2 | `admin` | 触发等待期扫描 → 案件不会生效 |
| 3 | `admin` | 处理异议 → 异议不成立 → 回到等待期（重新计时） |

## 18.6 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报"表不存在" | `DB_PORT` 没改成 Docker 映射的端口，连到了本机 MySQL | 检查环境变量 |
| 启动报"未配置资产加密主密钥" | 没设 `LG_KEK_KEYS` | 用 `openssl rand -base64 32` 生成，格式 `1=<base64>` |
| 启动报"JWT 密钥强度不足" | 密钥不足 32 字节 | 重新生成 |
| 资产解密失败 | KEK 与加密时不一致 | 确认 `LG_KEK_KEYS` 未变更；演示数据需删掉重建 |
| 登录频繁返回 429 | 限流触发（开发环境 30 次/分钟） | 等待一分钟后重试 |
| 通知一直不出现 | 发件箱未发布 / MQ 未连接 | 查管理端「任务与消息」的待发数量；确认 RabbitMQ 健康 |
| 等待期到点不生效 | 定时任务未到扫描时间 | 管理端点「触发等待期扫描」，或等 60 秒 |
