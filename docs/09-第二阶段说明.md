## 9.2 六个关键设计决策

### ① 统一响应与 HTTP 状态码绑定

`ErrorCode` 枚举同时携带业务码、HTTP 状态码与默认文案。业务码不是装饰，
它把四类失败明确分开：

| 场景 | HTTP | 业务码 | 前端应如何反应 |
| --- | --- | --- | --- |
| 未登录 / 令牌失效 | 401 | 40101 | 跳登录页 |
| 已登录但无权限 | 403 | 40301 | 提示无权限，留在原页 |
| 当前状态不允许 | 422 | 42201 | 提示具体原因 |
| 并发冲突 | 409 | 40901 | 提示刷新后重试 |

这四类混成 200 或混成同一个码，前端就只能靠猜。

### ② 默认拒绝的授权策略

```java
.anyRequest().denyAll()
```

新增接口必须显式加进白名单或规则里。反面做法是 `.anyRequest().permitAll()` 再逐个收紧 ——
那样任何一次遗漏都是**直接公开**，而且是静默的。

### ③ JWT 无状态 + 每次查账号状态

JWT 签名有效，不代表这个人现在还能用。用户被禁用后，旧令牌仍会通过签名校验直到过期。
所以过滤器在验签之后还要问一次 `UserAuthStateResolver.isActive()`。

这个接口在第二阶段返回 `true`（还没有用户表），第三阶段接入 `sys_user` 时**只改实现类**，
过滤器不动。

### ④ 认证失败不抛异常，只清空上下文

过滤器校验失败时如果直接抛异常，匿名接口（注册、登录、健康检查）也会被拦。
正确做法是静默清空 `SecurityContext`，由后续的授权规则决定该不该拒绝。

### ⑤ Redis 故障时的取舍已明确写死

登出黑名单查询失败时**放行**并记 WARN，而不是拒绝。理由：黑名单是"提前失效"机制，
令牌本身仍在 30 分钟有效期内且签名已通过；若改为 fail-closed，Redis 一挂全站不可用。
这是有意的权衡，不是遗漏 —— 代码注释里写明了。

### ⑥ 发布确认与路由失败回调分开处理

`publisher-confirm-type: correlated` 只告诉你 Broker 收没收到。
路由 key 写错时，Broker 收到后找不到队列，**confirm 依然是 ack，消息却被丢弃**。
所以必须同时开 `publisher-returns` + `mandatory` 并处理 `ReturnsCallback`。

## 9.3 运行方式

### 前提

本机 `3306`（MySQL）与 `6379`（Redis）已被占用，因此 Docker 实例改用非标准端口映射：

| 服务 | 容器内 | 宿主机 |
| --- | --- | --- |
| MySQL | 3306 | **13306** |
| Redis | 6379 | **16379** |
| RabbitMQ | 5672 / 15672 | **5673** / **15673** |
| 后端 | 8080 | 8080 |

### 启动中间件

```bash
cd docker
cp .env.example .env      # 首次；填写密码，LG_JWT_SECRET 用 openssl rand -base64 32 生成
docker compose up -d
docker compose ps         # 等待三个服务都变成 healthy
```

### 本地启动后端（推荐，改代码不用重建）

```bash
cd backend
export DB_HOST=localhost DB_PORT=13306 DB_NAME=legacy_guard
export DB_USER=legacyguard DB_PASSWORD=<见 docker/.env>
export REDIS_HOST=localhost REDIS_PORT=16379
export RABBITMQ_HOST=localhost RABBITMQ_PORT=5673
export RABBITMQ_USER=legacyguard RABBITMQ_PASSWORD=<见 docker/.env>
export LG_JWT_SECRET=<见 docker/.env>
mvn spring-boot:run
```

或在 `application-dev.yml` 之外用 IDE 的运行配置设置上述环境变量。

**注意**：如果把 `DB_PORT` 漏掉，会连到本机那台 MySQL 而不是 Docker 里的，
表现为"表不存在"—— 这是最容易踩的坑。

### 全容器启动

```bash
cd docker
docker compose --profile app up -d --build
```

### 测试

```bash
cd backend
mvn test
```

### 访问

| 地址 | 说明 |

| http://localhost:8080/actuator/health | 健康检查 |
| http://localhost:8080/swagger-ui.html | 接口文档 |
| http://localhost:15673 | RabbitMQ 管理台 |
